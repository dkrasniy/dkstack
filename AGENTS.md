# dkstack

A React app starter built on `@dkrasniy/ui`, the component library in `packages/ui`. The
app has TanStack Router, TanStack Query, the lint rules and the skills set up, and a docs
page for every component. A new app starts from a copy of this repo.

| doc                    | what it covers                                             |
| ---------------------- | ---------------------------------------------------------- |
| `README.md`            | Starting an app, the layout, the commands and the skills.  |
| `docs/overview.md`     | How the package, the app, the component docs and lint fit. |
| `docs/start-an-app.md` | Turning a copy of this repo into your own app.             |
| `docs/tokens.md`       | Every color, size, radius, shadow and easing token.        |

## Commands

```
npm run dev          vite on :5173
npm run build        tsc -b, then vite build
npm run verify       typecheck, lint, format check and tests. Run it before a PR.
npm run typecheck    tsc -b
npm run lint         eslint
npm run format       prettier --write
npm test             vitest, including the lint rule tests
```

## Rules that are enforced, not remembered

`eslint.config.js` carries the architecture's boundaries, and `eslint.config.test.ts`
asserts each rule still fires. If one blocks you, read the message: it says what to do
instead. Do not add an eslint-disable to get around one.

- `packages/**` cannot import the app, a router or a data layer. It takes data as props and
  reports changes through callbacks.
- A feature in `src/features/` cannot import another feature or `src/routes/`. From
  `src/app/` it can import only `errors.tsx`.
- Stores in `src/state/` cannot import features or routes.
- Animation is CSS only. `motion`, `framer-motion`, `react-spring` and `gsap` are blocked.
- Only `config.ts` reads `import.meta.env`.
- Cache keys come from `src/api/keys.ts`, never an inline array. The file holds keys only
  for queries the app makes, so add a key when you add a query and remove it with the query.
- Errors a user reads come from `describeError` in `src/app/errors.tsx`. Never render
  `error.message`.
- Icons come from hugeicons, never lucide.

## Conventions

- `@dkrasniy/ui` is an npm workspace package. `@/*` is `src/`, set in both
  `tsconfig.app.json` and `vite.config.ts`, which have to agree.
- `src/routeTree.gen.ts` is generated by the router plugin and committed. Do not edit it.
- UI primitives come from the shadcn CLI with the `base-luma` style. Run
  `npx shadcn@latest add <name>` from `packages/ui/`, and it writes into
  `packages/ui/src/components/`. Restyle what it writes to match the tokens.
- Every component in the package has a docs page in `src/features/components/entries/`.
  Add one when you add a component.
- Controls that are fully round by default use `rounded-pill`, so the Soft and Sharp corner
  shapes reach them. Use `rounded-full` only for shapes that stay circles, like avatars.

## Comments

Write none. Name things so the code says what it does. The only exceptions are a legal
header, a justified lint suppression, or behavior forced by an outside dependency that the
code can't show.

## Tests

- Write tests once a feature works, not while you build it. A test written mid-feature pins
  code that is still changing.
- Write a few tests for what a user or caller relies on: the main path and the edge cases
  that would break something real. Skip markup, styling, constants and anything the type
  checker already proves.
- When a test fails, fix the code. Change the test only when the behavior was meant to
  change, and say so.
- A bug with a cheap local test path is the exception. **tdd** applies: write the failing
  test first.

## Commits

- Use Conventional Commits: `feat:`, `fix:`, `docs:`, `refactor:`, `test:` or `chore:`, then
  a short summary of what changed, like `fix: align select rows`. Add a body when the
  reason isn't obvious from the subject.
- Never add a `Co-Authored-By` trailer or any other author, and never change git config,
  the author or the committer. The person running the agent is the only author.

## Skills

`.claude/skills/` holds the standards for this repo. Where a skill disagrees with a
convention this file or the code already sets, the convention wins.

- **better-writing** applies to any text a user reads: errors, empty states, labels and
  confirmations.
- **better-layout**, **better-typography**, **better-colors**, **better-ui** and
  **better-accessibility** apply when building or reviewing UI, each in its own area.
  **better-interface** runs all of them as one review, and **interface-review** does the
  same for a branch or PR. Run `/interface-review` or `/break` yourself; they don't start
  on their own.
- **principle-test-behavior-not-implementation** applies whenever you write or keep a
  test. Delete a test that would still pass if the code under it returned `undefined`.
- **tdd** applies only to bugs, as described under Tests.
- **write-docs** applies whenever you write or edit a README or anything in `docs/`.

To add a skill, put a folder with a `SKILL.md` in `.claude/skills/` and add a line for it
here.
